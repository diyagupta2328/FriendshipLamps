Friendship Lamps

A pair of connected lamps that communicate over WiFi. When a button is pressed on one lamp, the other lamp lights up and plays music from anywhere with an internet connection.

Project Overview

Friendship Lamps uses an MSPM0G3507 microcontroller and an ESP32-WROOM-32E WiFi module to connect two physical lamps over the internet. The MSPM0 handles local hardware control, including the button, LED strip, and UART communication. The ESP32 handles WiFi, MQTT messaging, and I2S audio playback through a MAX98357A amplifier.

MSPM0G3507 ESP32-WROOM-32E MQTT UART I2S Audio NeoPixel LEDs

How It Works

User presses the button on Lamp 1.

The MSPM0 detects the button press and sends a command to ESP32 #1 over UART.

ESP32 #1 publishes a message to an MQTT broker over WiFi.

ESP32 #2 receives the MQTT message from anywhere with WiFi access.

ESP32 #2 sends a command to MSPM0 #2 and plays music through the I2S amplifier.

MSPM0 #2 lights up the LED strip for 15 seconds.

The same process works in reverse when Lamp 2's button is pressed.

Hardware Components

Component Purpose
MSPM0G3507 LaunchPad Main microcontroller for button input, LED control, and UART communication.
ESP32-WROOM-32E WiFi module for MQTT communication and audio playback.
MAX98357A I2S Amplifier Drives the speaker using digital I2S audio from the ESP32.
SK6812 NeoPixel LED Strip 30 LED visual indicator that lights up for 15 seconds.
30mm Illuminated Arcade Button User input button with a built-in LED.
Speaker Audio output for the received lamp signal.

Dependencies

The MSPM0 firmware was developed in Code Composer Studio using the MSPM0 SDK 2.x. The ESP32 firmware was developed in Arduino IDE with ESP32 board support and the PubSubClient library. 

const char* WIFI_SSID     = "YOUR_WIFI_NAME";
const char* WIFI_PASSWORD = "YOUR_WIFI_PASSWORD";

ESP32 only supports 2.4GHz WiFi. For an iPhone hotspot, enable Maximize Compatibility.

Communication Protocols

GPIO Input

Button to MSPM0, active HIGH, pull-down, debounced.

UART

MSPM0 to ESP32 at 115200 baud, 8N1, using PA10 and PA11.

I2S

ESP32 to MAX98357A amplifier at 44100 Hz, 16-bit stereo.

NeoPixel 1-Wire

MSPM0 to SK6812 LED strip using bit-banged data on PA27.

WiFi + MQTT

ESP32 to ESP32 communication through broker.hivemq.com on port 1883.

Bidirectional Control

Either lamp can trigger the other lamp over the MQTT link.

Flashing Instructions

MSPM0

  1. Open CCS and import the uart_echo_interrupts_standby project example.
  2. Replace main.c with the provided file.
  3. Verify SysConfig for 115200 baud UART, PA27 output, and PA13 input with pull-down.
  4. Build and flash using the onboard XDS110 debugger or an external SWD debugger for the PCB.

ESP32

  1. Disconnect MSPM0 UART wires before flashing because GPIO1 and GPIO3 are used for programming.
  2. Open the .ino file in Arduino IDE.
  3. Select ESP32 Dev Module and the correct COM port.
  4. Fill in WiFi credentials.
  5. Click Upload.
  6. Reconnect UART wires after flashing.

Troubleshooting

Symptom Fix
ESP32 won't flash Disconnect LaunchPad wires from GPIO1 and GPIO3 first.
No MQTT connection Check that WiFi has internet access, use 2.4GHz WiFi, and enable hotspot Maximize Compatibility if using an iPhone.
LEDs don't light Confirm J21 and J22 are in BP position, PA27 uses PINCM60, and the LED strip receives 5V.
Button not detected Check PA13 PINCM35, pull-down configuration, and switch wiring to 3.3V.
No sound Check that MAX98357A SD is tied to 3.3V, Vin receives 5V, and GPIO26, GPIO25, and GPIO27 are connected correctly.
Only one direction works Each lamp needs its own MSPM0 and ESP32 fully wired.
